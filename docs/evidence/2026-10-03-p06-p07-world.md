## Object catalog

The production config remains exactly 25 unique object classes, exactly five per zone.

Every configured class now has a dedicated procedural visual path instead of exposing the collectible hitbox as the visible object. The hitbox root is invisible and non-queryable; readable geometry is built around it.

Implemented families include:
- Backyard: can, toy block, shoe, garden chair, barbecue
- Downtown: traffic cone, mailbox, bicycle, dumpster, compact car
- Industrial: pallet, barrel, tool chest, forklift, cargo container
- Airport: luggage cart, service cart, airport bus, jet stair, jet engine
- Megacity: street tree, city bus, billboard, crane section, building chunk

Vehicle/industrial families include details such as wheels, hubs, windows, lights, masts, forks, rails, ribs and latches rather than single-box silhouettes.

Object copies are capped at 6 per class in the world pass. Orbit visuals remain separately capped by the existing orbit slot limit.

## World / zones

Five zone-specific procedural art passes are implemented:

- Backyard: lawns, houses, warm windows, fences, trees
- Downtown: towers, windows, streetlights, crosswalk dressing
- Industrial: warehouses, storage tanks, pipe infrastructure
- Airport: terminal, glass frontage, control tower, taxi/runway markings
- Megacity: tall neon towers, spire and elevated skyrail dressing

Generic landmark cubes were removed.

## Gate architecture

- Zone bounds and unlock requirements are evaluated by pure ZoneRules.
- Production ZoneConfig is tested for five ordered, non-overlapping zones.
- Locked zone entry is rejected server-side.
- The player is returned to a safe point in the previous zone.
- Visible gate arches expose Gravity/Core requirements.
- Gate fields are tagged and switch locally between locked and OPEN state per player.
- Unlock feedback and actual zone-entry feedback are distinct events.
- HUD shows concrete requirements when a locked zone is attempted.
